# 07 — Program Risk Register

| Risk ID | Category | Severity | Description | Impact | Mitigation Strategy | Owner Specialty | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **RSK-001** | Security | **Critical (P0)** | Plaintext password storage in Firebase RTDB & SharedPreferences | User credentials exposed to database readers or device physical attackers | Eliminate `password` field from User model and local storage; rely strictly on Firebase Auth | Senior Security Architect | **Mitigated in Phase 1** |
| **RSK-002** | Security | **Critical (P0)** | Google Maps API Key exposed in `strings.xml` | Public abuse of Google Cloud Maps billing and quota depletion | Move key to `local.properties` + manifestPlaceholders; restrict key in Google Cloud Console | Senior Security Architect | **Mitigated in Phase 1** |
| **RSK-003** | Compliance | **High (P1)** | Google Play rejection due to `CALL_PHONE` permission | App removed or blocked from Google Play Store for telephony policy violation | Replace `ACTION_CALL` with `ACTION_DIAL`; remove `CALL_PHONE` permission | Product Engineer / Security | **Mitigated in Phase 1** |
| **RSK-004** | Usability | **High (P1)** | Registration form unscrollable under soft keyboard | Users on smaller screens cannot complete sign-up or submit form | Wrap layout inside `ScrollView` with `fillViewport="true"` and `adjustResize` | Principal Frontend Engineer | **Mitigated in Phase 1** |
| **RSK-005** | Reliability | **High (P1)** | App crash on Map startup due to uninitialized GoogleMap | Distributor app crashes immediately upon opening Tracking screen | Add null-safety checks in `LocationCallback` before accessing `myMap` | Mobile Platform Engineer | **Mitigated in Phase 1** |
| **RSK-006** | Performance | **Medium (P2)**| High GPS battery drain during disaster conditions | Survivor and distributor devices run out of battery in disaster areas | Implement adaptive location intervals with distance thresholds; remove toast spam | Senior Performance Engineer | **Mitigated in Phase 1 & 2** |
| **RSK-007** | Architecture | **Medium (P2)**| Monolithic Activity God-Objects prevent automated testing | High regression risk during feature additions; impossible to mock | Migrate to Clean Architecture with MVVM, ViewModels, and Repositories | Principal Architect | **Mitigated in Phase 2** |
| **RSK-008** | Reliability | **Medium (P2)**| Disaster zone network loss causing app freezing | App unresponsive when cellular towers fail in flood/cyclone regions | Enable Firebase offline persistence (`setPersistenceEnabled`) and disk write queues | Principal Backend Engineer | **Mitigated in Phase 3** |
| **RSK-009** | DevOps | **Medium (P2)**| Local SDK path dependency breaks new developer onboarding | New team members fail to compile project out of the box | Standardize `local.properties.example` and set up GitHub Actions CI | Senior DevOps / SRE | **Mitigated in Phase 1** |
| **RSK-010** | Database | **Low (P3)** | Inefficient RTDB tree structure for queries | Slow unindexed scans and excessive database billing | Added `.indexOn` indexing rules in `database.rules.json` | Senior Database Architect | **Mitigated in Phase 3** |
| **RSK-011** | Code Quality | **Medium (P2)**| Class name collision between `GoogleMap` Activity and Maps SDK | Compiler namespace confusion and fully qualified import workarounds | Renamed Activity to `MapActivity` and layout to `activity_map.xml` | Principal Architect | **Mitigated in Phase 2** |
| **RSK-012** | Reliability | **Medium (P2)**| Runtime `NullPointerException` on missing or refactored view IDs | App crashes on screen render due to outdated `findViewById` lookups | Enabled ViewBinding across 100% of Activities | Principal Frontend Engineer | **Mitigated in Phase 2** |
| **RSK-013** | Reliability | **High (P1)** | Ghost distributor markers remaining active on sudden phone disconnect | Survivors navigate towards offline or abandoned distributor locations | Armed server-side `onDisconnect().removeValue()` hook | Principal IoT Architect | **Mitigated in Phase 3** |
| **RSK-014** | Concurrency | **Medium (P2)**| Simultaneous distributor acceptance of the same relief request | Duplicate supply dispatch and chaotic field coordination | Enforced atomic Firebase `runTransaction` state machine transitions | Principal Backend Engineer | **Mitigated in Phase 3** |
| **RSK-015** | Usability | **High (P1)** | Viewport clipping and keyboard obscuration on small/medium Android screens | Form controls, submit buttons, and hero graphics clip off-screen | Universal `ScrollView`/`NestedScrollView` enclosure with `fillViewport="true"` and `adjustResize` | Responsive Experience Specialist | **Mitigated in Phase 4** |
| **RSK-016** | Accessibility | **High (P1)** | Sub-48dp touch targets and zero `contentDescription` on interactive navigation | Mis-taps under emergency panic and complete TalkBack screen reader failure | Enforced 48x48dp minimum touch bounds and descriptive strings across 100% of image elements | Accessibility & Inclusive UX Specialist | **Mitigated in Phase 4** |
| **RSK-017** | Usability | **Medium (P2)**| Empty placeholder screens (`Profile`, `Informations`) with zero usable data | Distressed survivors unable to view disaster guidance or verify their active role | Populated full user identity hub and comprehensive structured disaster safety guides | Creative Frontend Director | **Mitigated in Phase 4** |
| **RSK-018** | Architecture | **Critical (P0)**| Five unlinked activities and 38 compilation errors from legacy commit `25ac0de` | App failed to compile or crashed with `ActivityNotFoundException` when accessing requests/inventory | Resolved all 38 compilation errors, restored legacy color tokens, created missing drawables, and registered all activities in `AndroidManifest.xml` | Principal Full-Stack Engineer | **Mitigated in Phase 5** |
| **RSK-019** | Logistics | **High (P1)** | Double-allocation and phantom supply promises during concurrent request claims | Depots run out of physical stock while dispatchers promise rations to stranded victims | Automated atomic inventory reservation engine `ReliefWorkflowAutomator` with threshold alerts | Principal Automation Architect | **Mitigated in Phase 5** |
| **RSK-020** | AI & Triage | **High (P1)** | Mis-triage of trapped and bleeding victims under chaotic disaster text inundation | Critical trauma cases delayed while routine supply replenishments take dispatch priority | Implemented `ReliefTriageAdvisor` with keyword distress weighting, wait-time escalation, and bound guardrails $[0, 100]$ | Principal AI/ML Engineer | **Mitigated in Phase 5** |
| **RSK-021** | IoT / Telemetry | **Medium (P2)**| Telemetry loss and heap memory exhaustion during extended cellular blackouts | Distress field teams lose GPS continuity and unbounded location queues crash app | Implemented `OfflineTelemetryBuffer` with bounded FIFO ring buffer ($100$ items) and atomic reconnect batch syncing | Principal IoT Systems Architect | **Mitigated in Phase 5** |
